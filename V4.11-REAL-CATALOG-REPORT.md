# AmarangoElectro V16 — V4.11 Real Catalog Read-Only Gate

## Resultado ejecutivo

V4.11 conserva la capa visual V4.10 y deja funcionando el circuito completo:

`evidencia sanitizada → adaptador auditado → Product V16 → búsqueda/filtros → categoría → tarjeta → ficha → favoritos/compartir`

No se conectó producción. No se encontró en el checkpoint una URL, clave pública, recurso con RLS auditado ni snapshot exportado desde el catálogo productivo. Por seguridad no se improvisaron credenciales ni nombres de tablas. El piloto usa únicamente cuatro registros comerciales ya presentes en el laboratorio V4.10/V3, copiados a un fixture público sanitizado y rotulados explícitamente como **evidencia de laboratorio no verificada contra producción**.

## Normalización y contrato único

`V411AuditedPilotCatalogAdapter` valida el JSON con Zod, rechaza campos desconocidos, exige `visible: true`, no tiene red y no expone `insert`, `update`, `upsert`, `delete` ni RPC.

- ID V16: `v411-evidence:<id-origen>`.
- Slug: nombre normalizado más ID de origen; no usa posiciones de array.
- Precio: ARS entero positivo o ausente.
- Imagen: solo una URL HTTPS válida; en la evidencia actual es `null` y se muestra el fallback premium existente.
- Stock: `available` se normaliza a `in_stock`; cualquier otro estado queda `unknown`.
- Financiación: lista vacía porque no existe una política 2/4/6 auditada.
- Visibilidad: fail-closed; nunca se convierte un valor indefinido a visible.
- Objetos normalizados: congelados para detectar mutaciones accidentales.

Cliente, Asesor y Administración consumen los mismos IDs Product V16. La Administración agrega datos internos mediante un join local y aislado, no creando un catálogo alternativo.

## Buscador y filtros

- Búsqueda por nombre, marca, modelo, categoría y términos normalizados.
- Tolerancia a mayúsculas/minúsculas y acentos.
- Coincidencia numérica conservadora: un modelo no se amplía por coincidencias parciales inseguras.
- Filtros activos: marca, categoría, subcategoría/ruta, precio máximo y disponibilidad confirmada.
- Orden: recomendado, nombre y precio ascendente/descendente.
- Favoritos: locales, sin backend.
- Preparado para catálogo grande mediante resultados diferidos, lazy loading y render acotado a la ruta de categoría/búsqueda.

## Roles

- Cliente: producto, imagen/fallback, contado, financiación solo si existe, disponibilidad, favorito y compartir. Sin costo ni proveedor.
- Asesor: mismo Product V16, datos comerciales autorizados y compartir. Sin costo, proveedor, margen, inversión, comisión ni USD.
- Administración: conserva Admin Accelerator, Calculadora, Placas, Ofertas y operativa legacy. Puede ver costo/proveedor del fixture interno, pero V4.11 mantiene la edición remota bloqueada; las interacciones de laboratorio quedan locales.
