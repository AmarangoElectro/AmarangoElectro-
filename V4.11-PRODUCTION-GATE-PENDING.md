# AmarangoElectro V16 — V4.11 Production Gate Pending

## Decisión actual

**NO APTO PARA PRODUCCIÓN TODAVÍA.**

V4.11 está aprobado como checkpoint técnico read-only, no como integración real productiva. No se desplegó, no se modificó `main` y no se ejecutó ninguna escritura externa.

## Bloqueo principal: fuente real no auditada

Para avanzar de forma segura se necesita una de estas dos entradas:

### Opción A — Lectura Supabase auditada

1. URL exacta del proyecto.
2. Publishable key o anon key destinada al storefront; nunca `service_role`.
3. Nombre exacto de tabla o, preferentemente, vista pública de catálogo.
4. Schema/columnas reales y tipos.
5. Política RLS/SELECT revisada que limite la respuesta a campos públicos.
6. Consulta SELECT aprobada y acotada para el piloto.
7. Confirmación de la fuente canónica entre `tienda_catalogo`, `celulares_lista`, `tienda_productos_incremental` u otra fuente real.
8. Política de URLs públicas HTTPS para Storage/imágenes.

### Opción B — Snapshot manual sanitizado

Entregar un JSON de 5–20 productos exportado por un responsable autorizado, con:

- ID estable;
- nombre;
- marca;
- modelo;
- categoría/subcategoría;
- precio contado público;
- campos reales de cuotas 2/4/6, si existen;
- stock/estado y significado;
- visibilidad pública;
- URL pública HTTPS de imagen;
- fecha de precio/actualización;
- origen del registro.

Debe excluir clientes, teléfonos, credenciales, tokens, costos y datos privados de proveedor. Costos/proveedor pueden entregarse en un archivo administrativo separado si se aprueba expresamente su auditoría.

## Campos faltantes o ambiguos

| Campo/decisión | Riesgo si se asume | Requisito para aprobar |
|---|---|---|
| Fuente canónica | duplicados o divergencias | comparar datos reales de las fuentes |
| ID estable | URLs rotas o ventas mal relacionadas | clave persistente documentada |
| Visibilidad | exposición de ocultos | semántica y RLS confirmadas |
| Stock | mostrar disponibilidad falsa | significado de valores y regla pública |
| Imágenes | enlaces rotos/privados | bucket/ruta/HTTPS y fallback auditados |
| Cuotas 2/4/6 | precio comercial inventado | campos, fórmula y fecha de política |
| Fecha de precio | dato vencido | columna canónica y timezone |
| Destacados | campañas incorrectas | campo y regla pública |
| Categorías | productos mal ubicados | mapeo legacy → 22 entradas V4.10 |
| Costos/proveedor | fuga de información | separación servidor/rol y autorización |

## Gates antes de reemplazar producción

1. Validar fuente real y snapshot piloto con el dueño del catálogo.
2. Ejecutar auditoría de duplicados, IDs, precios, imagen, stock y visibilidad.
3. Probar SELECT/RLS con usuario anónimo/público y comprobar que no devuelve campos privados.
4. Activar el adaptador Supabase únicamente detrás de configuración de servidor y feature flag.
5. Repetir QA con productos reales en las seis categorías prioritarias.
6. Definir financiación 2/4/6; hasta entonces no mostrar cuotas inventadas.
7. Definir cache, paginación y límites para 1.200+ productos.
8. Validar URLs canónicas y compartir desde una URL de staging real.
9. Auditoría de permisos para Administración; mantener las escrituras desactivadas hasta un gate independiente.
10. Staging con métricas LCP/CLS/INP en Android real.
11. Plan de rollback y comparación V4.10/V4.11 antes de cualquier cambio productivo.
12. Aprobación humana explícita antes de producción.

## Fuera de alcance preservado

- Autenticación productiva Maxi/Angie.
- SQL, RLS, migraciones y Storage writes.

Revisar este checkpoint y entregar el recurso read-only auditado o el snapshot manual sanitizado. No avanzar al gate siguiente hasta esa revisión.
